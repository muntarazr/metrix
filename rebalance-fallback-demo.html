مثال عملي: Rebalance Fallback

السؤال

عندما المستخدم يعدّل مدة الخطة أو صعوبتها، النظام يستدعي AI لإعادة توازن الخطة. لكن ماذا يحدث إذا نفدت حصة AI (Quota)؟

الوضع الحالي في الكود

السيناريو: المستخدم غيّر المدة من 90 يوم إلى 30 يوم
المستخدم يعدّل المدة ← POST /api/goal/rebalance ← فحص الحصة ← الحصة نفدت!

الكود الحالي (rebalance/route.ts)

// المسار: src/app/api/goal/rebalance/route.ts const auth = await requireUser(req); if (auth.error) return auth.error; // فحص حصة AI const quotaResult = await requireAiQuota(auth.supabase, 'gemini', 'ai_edit'); if (!quotaResult.allowed) { // ✅ يوجد fallback محلي — لا يتوقف! const localResult = GeminiService.rebalancePlanLocally(params); return Response.json(localResult); } // الحصة متاحة — استدعاء AI const result = await GeminiService.rebalancePlan(params); return Response.json(result);

المشكلة

rebalance فقط عنده fallback محلي. أما plan و investigate فليس عندهم — يتوقفون تمامًا عند نفاد الحصة.

السؤال

تريد نضيف fallback محلي لـ plan و investigate أيضًا؟

أ) نضيف fallback للثنين
fallback محلي لـ plan و investigate — يضمن عدم التوقف أبدًا. مثال: إذا نفدت الحصة أثناء إنشاء الخطة، النظام يولد خطة بسيطة محليًا بدل ما يظهر خطأ.
ب) fallback بس لـ investigate
investigate فقط يحصل على fallback (تحقيق بسيط محلي). plan ينتظر المستخدم حتى تتوفر الحصة.
ج) إعادة محاولة تلقائية
النموذج يعيد المحاولة تلقائيًا بعد نفاد الحصة (wait and retry). قد يتأخر المستخدم عدة دقائق.
د) رسالة للمستخدم
نعرض للمستخدم: "الحصة نفدت، حاول لاحقًا" بدون أي fallback. بسيط لكن قد يحبط المستخدم.

مثال عملي للـ fallback المحلي

إذا اخترت الخيار (أ)، هذا مثال كيف راح يعمل:

// مثال: خطة محلية بسيطة عند نفاد الحصة function createPlanLocally(goal, duration, difficulty) { const tasks = [ { id: "t1", task: "مهمة يومية أساسية", frequency: "daily", impact_weight: 3, time_required_minutes: 30, completion_criteria: "إنجاز المهمة بالكامل" } ]; return { status: "ok", plan: { goal_summary: goal, estimated_total_days: duration, confidence: "low" }, tasks: tasks, is_local_fallback: true // علم أنه محلي }; }

ملاحظة: الـ fallback المحلي يكون بسيط ومحدد مسبقًا، يعطي المستخدم خطة قابلة للتنفيذ حتى لو ليست ذكية.
